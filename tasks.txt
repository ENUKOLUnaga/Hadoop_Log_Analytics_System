Phase 2: Log Ingestion and HDFS Block Analysis
----------------------------------------------
Task-2: Small Log File Storage
-------------------------------
1.Uploading file :
command:
hdfs dfs -put ~/logfiles.log /user/nagendra/logs/
2.identify how many blocks are created
command:
 hdfs fsck /user/nagendra/logs/logfiles.log -files -blocks -locations

Explain why the observed number of blocks is created
------------------------------------------------------

HDFS stores files in fixed-size blocks.
Block size = 128 MB
File size = 246 MB
Calculation:
246 MB / 128 MB = 1.92 → HDFS needs 2 blocks
So HDFS splits the file:
Block 1 = full block (128 MB)
Block 2 = remaining ~112 MB

Analysis of Block Allocation for Small Files:
----------------------------------------------
When a file is smaller than the block size (e.g., 1 KB, 10 KB, 1 MB):
HDFS still allocates one full block entry in the NameNode metadata.
A tiny file (say 5 KB) still uses one 128 MB block slot in metadata.
The actual disk usage may be small, but NameNode memory is still consumed.

How block size impacts performance
1. Parallelism:
More blocks then more map tasks then higher parallel processing
E.g., 8 blocks → 8 mappers
2. Storage efficiency:
Each block has metadata in NameNode.
More blocks = more NameNode load.
3. Fault tolerance:
Each block is independently replicated.
If block replication = 3 → each block stored on 3 different DataNodes.
